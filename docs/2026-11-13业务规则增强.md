# 业务规则增强：实现、验证与演示建议

日期：2026-11-13。当前为本地 v0.7.0 增强，未发布站点、推送仓库或更新网盘提交包。

## 本轮增加的作品亮点

本轮从“表格基础质量检查”进一步支持“业务约定核验”：使用者自己定义条件，由本机确定性计算执行，再从结果回到来源记录。无需模型 API，不依赖生成式模型判断数值是否合规。

| 已实现功能 | 对使用者的作用 | 可展示的工程能力 |
| --- | --- | --- |
| 四类自定义规则 | 检查必填、字段唯一、数值范围、允许值列表 | 规则建模、输入校验与确定性计算 |
| 交互结果卡 | 分别展示通过、违规和跳过数量，切换规则查看证据 | 清晰的数据口径与交互反馈 |
| 原始记录核验 | 由违规项打开完整记录，保留原数据集行号 | 结果可追溯，而非只展示分数 |
| 本机保存与刷新恢复 | 为当前数据集保存最多 12 条规则 | 状态持久化和旧版本兼容 |
| 清洗后自动复检与撤销 | 清洗保留规则，重新计算；撤销恢复原数据及规则 | 完整且可逆的操作流程 |
| 两类导出 | 全部或单条规则违规 CSV、Markdown 检查报告 | 可交付结果与说明口径 |
| 质量页分区导航 | 快速前往基础问题、业务规则、字段详情 | 长页可用性与键盘焦点管理 |

以上是作品可展示的实际能力，不代表赛事官方承诺加分，也不能据此预测具体分数。

## 规则口径

- 必填：空值、空字符串和仅有空白的文本视为违规；数值 0 是有效值。
- 字段唯一：非空值转换为文本并去除首尾空白后比较，标出重复组里的所有记录；例如同一编号出现两次，两条均待核验。不同于基础检查中“多余重复行”的计数。
- 数值范围：上下限均含边界，可单侧不限。非空但不能解析为有限数值的内容违规。
- 允许值列表：每行一个值，最多 100 项，每项最多 200 字。去除首尾空白，区分大小写。
- 除必填外，其余规则跳过空值并单独计数。通过率 = 通过记录数 / 已检查记录数。无可检查记录显示“未检查”，不能当作全部通过。
- 检查完整当前数据集，不受分析筛选影响。同一记录可以触发多条规则，违规项总和不等于去重后的记录数。
- 规则不会修改原始数据，也不意味着符合规则的数据必然业务正确。

## 可直接用于答辩的 90 秒演示

1. 打开质量检查，点击页内“业务规则”。解释：“完整率高不代表符合业务约定，因此这里允许用户定义业务规则。”
2. 用内置合成零售数据，选择“订单编号 + 字段唯一”。结果为 6 条违规，分别对应 3 个重复编号的全部成员。
3. 打开第 45 条来源，核对订单编号 DP000045，说明记录序号对应完整数据集。
4. 添加“销售额 + 必填”，定位第 323 条空值。可再设置销售额范围 0–1000，演示上下限交互和跳过空值数量。这个范围只是演示条件，不是零售行业的真实标准。
5. 执行去重清洗：规则保留，订单编号违规变为 0；点击撤销，恢复为 6。说明处理可复检、可撤销。
6. 展示规则检查报告与违规 CSV 的导出入口，说明结果可以交给数据提供方核对。

如需保持原始演示数据，请在清洗演示后撤销。旧视频、线上页面和提交包尚未同步本轮功能。

## 实现与限制

计算位于 `lib/business-rules.ts`，界面位于 `components/exploration/business-rules.tsx`，规则经 `lib/workspace-tools.ts` 校验后恢复。旧工作空间默认规则为空，切换数据集不继承旧规则；同一数据集清洗保留规则。

每条规则页面保留前 200 项证据、每页 8 项，但计数覆盖全部记录。违规清单单次最多 50,000 项，超过时明确提示选择单规则分批导出，不能静默截断。报告是本次计算的静态摘要，没有后台定时巡检或通知服务。
