## 真实模型验证

本机从 `.env.example` 复制为 `.env.local` 后填写，禁止提交此文件。在本机执行：

```powershell
node scripts/eval-model.mjs
```

调用 31 道固定合成样本题，记录计划、实际/期望数值、是否一致与耗时。会使用自己的 API 额度。只有 `status=passed`、`mode=model` 且源码指纹一致才可作为本版本证据；小样本结果不代表通用准确率。无密钥时退出并写 blocked 记录。

## 保留开发历史迁移仓库

本项目已使用 GitHub 公开仓库 [233-arch/datapilot-chuanzhibei](https://github.com/233-arch/datapilot-chuanzhibei)。公开仓库不需要评审测试账号。`scripts/verify-review-repository.mjs` 使用不带认证头的 API 和禁用凭据助手的 Git 读取，核对默认分支与本地最终提交一致、README/环境模板/锁文件/PDF齐全，生成验证证据。

提交检查使用验证证据而非手填时间；本地新增提交后需重新推送并验证，避免旧证据套用。GitHub Actions提供独立检查；真实模型固定集已有独立证据，实际视频仍需补齐。

交付目录提供 `DataPilot-history.bundle`。在自己的空目录中：

```powershell
git clone E:\chuanzhi\datapilot\outputs\DataPilot-history.bundle DataPilot-review
cd DataPilot-review
git remote set-url origin <自己的GitHub或Gitee空仓库URL>
git push -u origin HEAD
```

仓库地址与评审权限需真实存在并实测。将第三方版权声明、环境模板、锁文件和说明一并保留；不要把 `.env.local`、个人文件、API 密钥或临时输出上传。ZIP 适合查看代码，bundle 才保留提交历史。

## 检查与冻结

复制 `submission/team.example.json`、`submission/review.example.json` 为同目录的实际文件，填写后运行：

```powershell
node scripts/check-submission.mjs
```

实际配置文件默认忽略，团队应公开的信息仍需补到 README。脚本检查匿名仓库验证证据、材料路径、真实评测证据与 PDF 审查指纹；视频存在时使用 ffprobe 核对规格（可通过 `DATAPILOT_FFPROBE` 指定路径）。普通话讲解、业务真实性与资格需人工确认，不能只填写时间字段就宣称完成验证。

最终提交前冻结 Git 提交、源码 ZIP、PDF、MP4 和评测记录，确认全部对应同一版本，并按当前赛事入口提交。不承诺获奖或主办方预认定合规。
