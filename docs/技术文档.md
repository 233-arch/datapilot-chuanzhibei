# 数问 DataPilot 技术说明

版本 v0.7.0 · 2026-11-16

河南农业大学 · B组 · 疯狂星期四

## 架构与运行流程

系统围绕单表分析构建，前端保存工作空间状态，纯函数模块负责数据处理，服务端路由负责可选的模型通信。九个 hash 页面共用当前数据、筛选与分析计划；页面地址不包含原始数据或 API 凭据。

数据流程：导入文件 → 解析与类型确认 → 数据剖析 → 质量核对 → 生成或配置分析计划 → 校验计划 → 确定性计算 → 图表与来源 → 报告或备份。

| 层次 | 主要模块与职责 |
| --- | --- |
| 交互层 | app/page.tsx 与 components/exploration：导航、导入向导、助手、图表、质量与报告。 |
| 计算层 | lib/data-engine.ts、quality-audit.ts、business-rules.ts：解析、聚合、问题定位与规则检查。 |
| 分析工作流 | analysis-templates.ts、report-draft.ts、report-bundle.ts：场景配置、草稿与报告输出。 |
| 存储层 | local-store.ts、workspace-snapshot.ts、workspace-backup.ts：项目保存、迁移与备份恢复。 |
| 模型边界 | 服务端 API 路由、模型配置及 Zod 结构校验：请求模型并约束返回值。 |

## 界面与响应式

桌面使用分组侧边栏、白色工作区和绿色重点；助手按需展开。手机提供常用底部导航和完整页面选择器。图表可独立收起设置，分析记录支持搜索、空状态和分批显示；键盘可操作导航、弹窗及报告演示。

## 导入与计算口径

支持 CSV、TSV、XLSX。CSV 处理 BOM、引号、单元格换行和常见中文编码回退；拒绝不一致列数、重复表头、危险对象字段及超限文件。XLSX 使用 read-excel-file，可选择工作表、表头与字段类型，只读取公式缓存值，不重新计算公式。

单文件不超过 25 MB，同时限制 20,000 行、80 列；CSV 解码后按 UTF-8 字节量再次检查。XLSX 还检查声明展开大小 64 MB 等内部限制，导入数据 JSON 不超过 30 MB。项目备份单独限制为 75 MiB。

缺失保持为空，数值聚合排除缺失和无效值，均值分母为有效记录数。纯日期按日历日期处理；非法日期不会自动滚动成其他日期。分组支持 sum、mean、count、max、min 与日/月时间粒度。筛选按 AND 合并。

## 质量检查与业务规则

质量检查覆盖整个当前数据集，不继承分析筛选。计数覆盖全部记录，页面保留最多 200 项问题证据；问题清单单次最多导出 50,000 项，超限需要分批。清洗先展示前后预览，执行与预览使用一致结果，并保留一次会话内撤销。

最多配置 12 条业务规则。必填检查空值；唯一、数值范围和允许值规则跳过空值，并单列跳过数。唯一规则标记重复组的全部成员，因此与整行去重的“多余记录数”不同。规则不自动修改原始数据。

## 图表解释

图形颜色仅用于区分维度或数值变化。占比图不用于均值、极值、负值或非正合计；展示 Top N 时说明范围。周期诊断按共同口径比较两个期间，覆盖天数不同时提示影响，不把金额差额直接解释为业务原因。

## AI 使用与可核验边界

无 API 时，本地助手采用固定规则识别概览、质量、字段说明、常用统计与有限追问。无法识别或存在歧义时提示补充口径，不伪造生成式回答。

接入个人 API 后，问题与受限摘要发往配置的模型服务。模型调用 create_analysis_plan 等固定工具，返回结构化计划；Zod 与真实字段白名单校验指标、维度、筛选、枚举和显示条数。浏览器执行前再次验证，并以本机原表计算数值。

模型不输出最终统计值，也不执行模型任意 JavaScript 或 SQL。计算口径中的 SQL 是只读示意。用户可预览并确认计划，查看筛选匹配数、有效记录、排除数及分组来源。

## 知识检索与证据回答

业务文档按段切分，用中文双字词项、英文词和 TF-IDF 稀疏向量进行本机检索，最多选取 4 段相关文本。回答通过固定引用编号与原句序号关联原文；系统校验引用存在和逐字对应。不使用外部向量数据库，也不把检索分数当作可信概率。

证据导读让模型选择已有统计事实编号，由程序渲染对应数字。引用存在仍需人工核对语义适用性，不构成业务真实性认证。多步骤规划、文档问答和证据导读均保留取消或失败反馈。

## 凭据与数据范围

访客凭据只驻留当前页面内存，不写入 IndexedDB、源码、项目备份和报告；刷新后清除。模型请求不回退使用部署者共享密钥。原始表格在本机处理，但用户问题、选定摘要及检索片段会按所用功能发送给配置的模型服务。用户写入数据或笔记中的秘密内容不会被自动识别和删除。

## 保存恢复与交付

IndexedDB 分开保存数据载荷与配置，修改报告标题等配置无需重写整表。500 ms 防抖保存并显示状态；恢复失败时暂停编辑，配额失败保留上次成功版本。多标签页使用版本校验，避免静默覆盖其他标签的更新。

本机数据集库最多保存 8 份项目，切换前保存当前副本。完整备份包含当前项目数据、规则、收藏、分析记录、业务文档与报告草稿；其他项目需要单独备份。恢复前校验版本、结构、字段与 SHA-256，显示预览，确认后创建独立项目。校验用于发现损坏，不证明作者身份。

## 报告与模板

模板先要求真实字段映射，再预览拟创建的基础图表和必填规则；应用时避免重复收藏，并在条件允许时撤销。模板不自动推断业务阈值。

报告草稿支持标题、章节选择、排序与“发现、证据、建议”批注。核验标记绑定当前数据和配置，相关内容改变后失效；标记由使用者确认，不代表系统保证正确。演示模式展示选中章节，支持左右键翻页和 Esc 退出。HTML 与 Markdown 输出进行文本转义，CSV 对公式前缀处理。

## 性能与限制

20,000 行 × 80 列合成数据曾在 Node v24.19.0 测得：剖析约 253 ms、聚合约 14 ms、备份生成约 244 ms、备份校验恢复约 569 ms。这是单次函数基线，不是浏览器端响应承诺或并发压力测试。

目前以本机单人使用为主，没有多用户实时协作、账号权限系统、云数据同步或自动因果推断。浏览器清理站点数据会移除本机工作，外部备份仍然必要。

## 验证与本地复现

本轮 211 项自动检查通过，覆盖核心计算、字段校验、本地问答、数据预览、业务规则、导出、备份往返、草稿恢复、存储迁移、事务回滚及多标签冲突。TypeScript 检查与生产构建通过。此次 UI 搜索、空状态和图表设置收起展开进行了浏览器核对。

历史模型评测保留为独立证据：2026-10-26 固定计划题集 31/31 通过。本轮没有重新调用外部模型，历史记录不得当作当前版本实时 API 验收。没有新增真人访谈或官方评分。

## 运行步骤

1 解压源码 ZIP 到普通目录，安装 Node.js 22.13.0 或以上版本。

2 在源码目录执行 npm ci --include=dev --include=optional --no-audit --no-fund。

3 执行 npm run dev，按终端实际显示地址打开浏览器；本项目常用 http://localhost:5173/。首次打开无需 API，可使用合成样例。

4 自动核验依次执行 npm test、npm run typecheck、npm run build。使用模型前在设置页面配置个人 API，不将密钥写入公开源码。
