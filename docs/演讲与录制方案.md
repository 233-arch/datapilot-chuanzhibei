# 数问 DataPilot 演讲与录制方案

版本 v0.7.0 · 2026-11-16

河南农业大学 · B组 · 疯狂星期四
队员 刘宗柯、陈世航、刘兴海　指导老师 唐琦

本方案供团队录制约 7 分钟的作品演示使用。主线是让观众看到一份表格怎样从问题走到可核对的报告。建议由一位主讲配一位操作人员完成；这是录制建议，不是成员实际分工声明。

## 时间与画面安排

| 时间 | 展示画面 | 讲清的重点 |
| --- | --- | --- |
| 0:00–0:35 | 首页与项目名称 | 团队、使用场景和分析流程。 |
| 0:35–1:15 | 数据集与数据明细 | 自己的文件可导入，数据可搜索核对。 |
| 1:15–2:20 | 质量检查 | 定位重复、预览清洗、执行并撤销。 |
| 2:20–3:35 | 首页提问与图表 | 先预览计划，再计算，收起设置查看图表。 |
| 3:35–4:35 | 来源明细与业务诊断 | 数字可追溯；周期差异不能直接当因果。 |
| 4:35–5:25 | 助手或智能分析 | 本地功能与真实模型功能的边界。 |
| 5:25–6:25 | 洞察报告与演示模式 | 章节、批注、核验、翻页与导出。 |
| 6:25–7:00 | 项目备份与首页 | 可恢复工作，说明验证和边界，结束。 |

目标时长包含鼠标操作和停顿。正文台词是讲解骨架，实际语速和彩排耗时决定取舍。若超过 8 分钟，先删诊断与备份的详细操作，保留质量、计划、来源和报告。

## 录制入口

启动本地项目后打开 http://localhost:5173/#/overview。使用内置合成“零售经营数据_2026.csv”，无筛选、未清洗状态；清洗演示后务必撤销，再继续后面的统计展示。

## 开场与数据准备台词

大家好，我们是河南农业大学 B 组的疯狂星期四团队，成员是刘宗柯、陈世航、刘兴海，指导老师是唐琦。我们的作品是数问 DataPilot。它面向课程实验和小规模表格分析，希望把一份数据从导入、检查、提问，一直连接到可以核对的报告。

做数据分析时，一个常见问题是图画出来了，却不清楚哪些记录参与了计算；使用模型回答时，也可能只得到一句难以复核的结论。我们的处理方式是把问题理解与数值计算分开，让每个主要结果都能回到真实记录。

现在展示的是内置合成零售样例，包含 1,251 条记录和 9 个字段。用户也可以导入自己的 CSV、TSV 或 Excel。进入数据明细后，可以搜索、排序和选择显示字段。不同页面使用同一份工作空间，切换页面不用重新上传。

## 对应操作

首页停留约 5 秒；进入“我的数据集”展示导入入口；进入“数据明细”，搜索“华东”，停留展示匹配结果，再清空搜索。不要把页面搜索误说成全局联动筛选。

## 质量检查台词

分析之前先检查数据。这里能看到缺失、重复和无效值，也能定位到具体记录。比如重复记录可以查看首次出现的位置，避免只给出一个问题总数。

点击清洗时，系统先显示将发生什么变化：默认去重会把 1,251 条记录变为 1,248 条。确认后再执行，并立即复检。如果操作不符合预期，可以撤销，恢复原始数据和分析状态。金额缺失不会擅自填成零。这里还可以配置业务规则，例如字段必填或订单编号唯一。

## 对应操作

进入“质量检查”→ 查看重复记录 → 打开清洗预览 → 只演示默认去重 → 执行 → 展示记录数变化 → 撤销。停顿确认恢复为 1,251 条，再继续。

## 从问题到图表台词

回到首页，我们输入“按月查看销售额趋势”。在没有接入 API 时，本地助手也支持常用的趋势、排名、占比和统计问题。它会先显示可检查的分析计划，确认日期、销售额和合计口径，再执行。复杂语义则可以选择接入个人模型服务。

来到图表页，维度、指标和汇总方式可以直接调整，图表会重新计算。需要展示时收起设置，整个区域就留给结果。图表还可以切换明细或放大查看，鼠标选中分组后显示准确数值。

在当前未经清洗、没有筛选的样例中，销售额合计是 1,950,881。共有 1,250 条记录参与销售额计算，另外一条因指标缺失或无效被排除。这样的说明可以帮助使用者区分总记录数和有效记录数。

## 对应操作

首页输入问题 → 展示待确认计划 → 确认并进入图表 → 点击“收起设置” → 选中八月或打开对应来源入口。若助手已打开，先关闭侧栏，让来源明细更清楚。

## 来源与诊断台词

这里的八月合计为 371,600。点击来源，可以检查构成这个结果的记录。图表的作用不是替代核对，而是帮助我们找到需要核对的位置。

业务诊断进一步比较两个期间，并按同一分类展示两期数值和增减。如果日期覆盖天数不同，系统会提示可能影响合计。分组变化说明差额来自哪里，但还不能直接说明为什么变化，业务原因需要结合实际材料判断。

## 对应操作

点击“查看 2026-08 来源明细”核对数值后关闭窗口；进入业务诊断，选择两个有数据的期间，展示一组两期横柱及来源。周期范围以页面实际设置为准，不照读未核对的差额。

## AI 与技术亮点台词

我们的 AI 设计重点是约束和验证。接入个人 API 后，大模型负责把自然语言转换成结构化计划，程序检查字段是否存在、参数是否合法，再由本机引擎计算。不会直接执行模型生成的任意代码，也不会把模型随口给出的数字当统计结果。

智能分析还支持多步骤规划、业务文档检索与引用问答。相关片段先在本机检索，再按功能需要发送给所配置的模型服务，回答可以回到原句。引用并不能自动证明结论正确，使用者仍然需要检查。

当前这一段如果没有接入 API，演示的是本地规则能力。真实模型能力需要个人 API 和可用额度，不能把本地回答当作实时模型返回。

## 两种可选画面

已配置且已测试成功：录制前完成配置，镜头中不展示密钥；现场演示一个已彩排的结构化分析计划。未配置或调用失败：保留本地助手画面，讲解结构与边界，可展示已有历史评测记录并说清日期，不能演成当前实时调用。

## 报告交付台词

分析完成后，我们将需要保留的结果收藏并放到洞察报告。这里可以选择章节、调整顺序，填写发现、依据和建议。核验标记会随数据或配置变化而失效，提醒我们重新检查。

进入演示模式后，只展示选中的章节，支持左右键翻页和退出，便于课堂展示与汇报。报告也可以导出为 HTML 或 Markdown，保留统计口径与说明，而不只是复制几张图。

## 对应操作

收藏当前图表 → 进入洞察报告 → 修改标题为“零售经营分析报告” → 编辑一条简短批注 → 展示核验入口 → 点击“演示报告”，翻页后按 Esc 退出。若只有一章，说明单章展示，不人为制造多页效果。

## 结束台词

最后，项目备份可以保存当前数据、分析配置和报告草稿，恢复前先校验并预览。它帮助我们把一次分析继续做下去，但本机备份不等于云同步。

当前版本完成了 211 项自动检查、类型检查和生产构建，并核对了桌面与手机交互。我们希望数问成为一个适合课程和小规模数据探索的工具，让数据质量、计算口径和分析结果都能被看见、被检查。以上是我们的展示，谢谢大家。

## 录制前准备

按已有参赛材料要求准备 5–8 分钟、至少 1080p、普通话讲解的 MP4；最终上传入口如有更新，以其提示为准。采用本包 v0.7.0 源码，先完整彩排一次。建议浏览器 1920×1080、缩放 100%，隐藏通知并关闭与演示无关的标签页。

检查无全局筛选、样例未清洗、窗口宽度充足；为报告准备至少一章。先备份重要项目。录制前若使用 API，先测试连接和问题，关闭设置后再开始录屏。不要录入或展示密钥。

剪辑可缩短等待，但不要拼接成不存在的操作结果。每次关键动作停留 1–2 秒，鼠标不要连续绕圈。最终播放 MP4，检查声音、文字清晰度、时长及版本一致性。

## 问题应对

| 情况 | 处理 |
| --- | --- |
| 模型超时或失败 | 明确说明当前未得到模型结果，切回本地助手；不把缓存或规则回答冒充实时模型。 |
| 数字与稿件不同 | 先核对当前数据集、筛选和清洗状态，以页面实际值为准；不要为了对上台词改数据。 |
| 被问到创新在哪里 | 演示计划校验、来源追溯、清洗预览撤销、报告核验与恢复等实际操作。 |
| 被问到使用规模 | 说明 25 MB、20,000 行、80 列的当前边界；不声称海量数据处理或生产级多人协同。 |
| 被问到已有成果 | 此前未发表、未获奖；历史模型评测与本轮本地验证分别说明。 |
