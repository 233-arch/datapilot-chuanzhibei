# 数问 DataPilot 演讲与录制稿

疯狂星期四团队  河南农业大学  B组

队员 刘宗柯 陈世航 刘兴海    指导老师 唐琦

本稿用于边操作边讲解，目标时长约7分30秒。正文可以直接朗读，“操作提示”和时间标签不用念。每次关键操作停留1至2秒；实际时长以彩排为准。

操作提示  打开 http://localhost:5173/，选择“零售经营数据_2026.csv”，清除筛选并保留原始数据。准备至少一项报告内容。AI段落根据是否接入API二选一。

## 1 开场介绍

0:00 - 0:35

操作提示  展示工作台首页。

各位评委老师好，我们是来自河南农业大学的“疯狂星期四”团队。我们的作品是“数问 DataPilot”，一个面向课程实践和日常表格分析的 Web 应用。

面对一份数据，使用者通常需要解决三个问题：数据是否可靠、应该怎样分析、结果从哪里得来。我们的项目围绕这三个问题，将数据检查、交互图表、分析助手和报告整理连接起来，让一次分析能够从导入开始，形成可以核对的成果。

## 2 数据导入与工作台

0:35 - 1:15

操作提示  展示当前数据卡片，进入“数据明细”，搜索一个地区，再清空搜索。

这里使用的是项目内置的合成零售数据，共有1,251条记录、9个字段，包括日期、地区、产品类别、销售额和利润等信息。

项目支持 CSV、TSV 和 Excel 文件。导入之后，系统会识别字段类型，并生成基本统计。

在数据明细页面，我们可以搜索记录、排序、选择显示字段，也可以导出筛选后的结果。这些操作帮助使用者先了解数据内容，再决定分析方向。

## 3 数据质量与清洗

1:15 - 2:05

操作提示  进入“质量检查”，展示缺失与重复问题；打开清洗预览，执行去重后撤销。

分析之前，我们先检查数据质量。

这份示例数据中有6个缺失单元格和3条完全重复记录。系统给出问题数量、问题位置和原始记录，方便逐条核对。

清洗之前，可以先查看变化预览。例如去除重复记录后，数据量会从1,251条变为1,248条。确认后再执行，也可以撤销最近一次清洗。

这里我撤销清洗，恢复原始数据，保证后面的演示使用同一份数据。对于金额等数值字段，缺失值会被单独处理，统计时显示有效记录和排除情况。

## 4 交互图表与结果追溯

2:05 - 3:10

操作提示  进入“图表分析”，展示按日期统计的销售额趋势，收起设置；点击“2026-08”的来源入口。

接下来，我们查看销售额的月度变化。

使用者可以选择分组维度、统计指标和汇总方式，也可以切换柱状图、折线图等表达形式。设置区域可以收起，让图表获得更多展示空间。

在当前数据中，八月销售额合计为371,600。点击来源入口，可以查看组成这个结果的217条记录。

这样，图表中的数字就有了可以核对的依据。使用者既能看到趋势，也能进一步检查具体记录，理解统计范围和计算口径。

操作提示  关闭来源窗口，再继续下一段。

## 5 分析助手与 AI 技术

3:10 - 4:25

操作提示  打开分析助手，输入“按月查看销售额趋势”，展示分析计划，核对后应用。

对于不熟悉图表配置的使用者，我们提供了自然语言分析入口。

例如输入“按月查看销售额趋势”，系统会先给出分析计划，包括使用哪个字段、怎样分组、采用什么汇总方式。使用者确认之后，程序再执行计算并更新图表。

## 未接入 API 时朗读这一段

当前演示使用的是本地规则助手，可以完成常用统计、趋势、排名和质量摘要，不需要 API。对于更复杂的自然语言理解，项目提供个人 API 接入入口。本次画面中的结果来自本地规则和计算，没有调用大模型。

## 已接入且现场调用成功时改读这一段

当前已接入个人 API。大模型负责理解问题并生成结构化分析计划，程序会检查字段和参数，再交给本机计算引擎执行。这里展示的是本次模型请求生成的计划，统计结果由数据计算得到。

操作提示  上面两段只选一段朗读。接着继续下面的共同台词。

这套设计把问题理解、计划确认和结果计算分开，让分析过程更容易检查。项目还提供多步骤规划和业务文档引用问答入口，用于扩展更复杂的分析场景。

## 6 业务诊断

4:25 - 5:05

操作提示  进入“业务诊断”，展示两个有数据的时间段及分组对比。

当我们发现某个指标发生变化时，还需要知道变化主要来自哪里。业务诊断可以比较两个时间段，并按照地区、类别等维度展示两期数值与增减。点击分组，还可以继续核对来源记录。

如果两个期间覆盖的天数不同，系统会提醒使用者注意统计口径。这里展示的是变化的分布，具体业务原因仍然需要结合实际情况判断。

## 7 手机与平板适配

5:05 - 5:45

操作提示  切换手机390×844，点击底部导航、打开助手；再切换平板768×1024和1024×768。

我们也考虑了不同屏幕下的使用体验。手机端采用底部导航，全部功能页面仍可以通过页面选择器进入。图表设置可以收起，分析助手按需打开，让有限的屏幕空间优先用于当前任务。

平板支持横竖屏布局调整，切换尺寸后，当前数据和分析配置保持不变。这里展示的是浏览器响应式模拟，重点验证页面能否正常阅读，以及关键功能能否继续操作。

## 8 报告整理与成果展示

5:45 - 6:45

操作提示  恢复桌面尺寸，进入“洞察报告”；展示章节选择、批注和演示模式。

分析完成之后，我们可以把需要保留的发现整理为报告。报告页面支持选择章节、调整顺序，并填写发现、依据和建议。核验标记帮助使用者记录哪些内容已经检查；当相关数据或配置变化时，需要重新核对。

进入演示模式后，可以逐页展示选中的内容，适合课堂汇报和项目交流。报告也可以导出为 HTML 或 Markdown，方便保存与分享。

此外，项目备份能够保存当前数据、分析配置和报告草稿，恢复前会先进行校验和预览，方便之后继续分析。

## 9 总结

6:45 - 7:20

操作提示  回到首页，最后停留在项目名称与工作台画面。

目前，项目已完成211项业务与交互相关自动检查，类型检查和生产构建也已通过，并同步到公开 GitHub 仓库。

我们的作品主要服务于课程实践和中小规模表格探索，当前支持单文件最多25 MB、20,000行和80列。后续还会继续完善真实设备兼容性和更多业务场景验证。

数问 DataPilot 希望带来的价值，是让使用者能够看见数据质量、理解分析过程，并追溯结果依据。以上是我们的项目展示，谢谢各位评委老师。
